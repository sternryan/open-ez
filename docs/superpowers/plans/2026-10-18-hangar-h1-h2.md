# Hangar H1 + H2 (decision records, Hangar index, briefing room) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mod-EZ decision records with gates, a deterministic mission calculator, the first record
(powerplant + fuel + tank resin) filled from registered sources, a Hangar index page, and a briefing
room inside the player where the owner talks a record through with the council and closes it.

**Architecture:** Records are YAML under `data/hangar/`, loaded and gated by a new `hangar/` Python
package that reuses `core.sources` (citations) and `core.ledger` (mass/CG). `guide.build_site` emits
`hangar.json`, and the lab (Vite + TypeScript) gets two new pages, `hangar.html` and
`briefing.html`, read-only on the public site. A stdlib HTTP companion service, run privately by the
owner, adds the council (an OpenAI-compatible chat endpoint set by env vars), transcripts outside the
repo, and record writes.

**Tech Stack:** Python 3.11+, PyYAML, stdlib `http.server` + `urllib` (no new Python deps), pytest;
TypeScript + Vite 8 in `guide/lab`, `node --import tsx --test`.

**Spec:** `docs/superpowers/specs/2026-10-18-hangar-briefing-room-mod-ez-design.md` (approved 2026-10-18).
H3 (Mod-EZ in the shop) is out of this plan: it waits for rehearsal phases 1 and 2 to merge.

## Global Constraints

- Public repo: no owner/family names, airports, addresses, personal weights, host names, tailnet
  addresses or model-lane names in any tracked file. `guide.leakcheck` must pass on a `--public` build.
- Every factual value carries a citation `<id>:p<page>` whose id is in `data/sources/registry.yaml`
  (web pages use `:p1`, as the existing `wicks-ra5277:p1` does), or is flagged `derived` (with method),
  `unknown`, or `judgment` (an advisor's opinion). Never upgrade a flag without a source in hand.
- The book build is untouched: no edits to `guide/graph/*.yaml`, `data/mass_ledger.yaml` or `core/*_book.py`.
- The council runs only on an owner request in the briefing room; never on a timer, never at build time.
- The shop and the public site work with no backend and no model.
- Transcripts and private overrides live only in `$HANGAR_PRIVATE_DIR`, which must resolve outside the repo.
- Exact UI copy: `awaiting briefing` (shop/index status for open or reopened records); `decided in briefing N`.
- Advisor roles, fixed ids: `propulsion`, `structures`, `fuel-systems`, `aero-flight-test`, `historian`.
- Record statuses: `open`, `decided`, `reopened`. Confidence: `low`, `medium`, `high`.
- Name: the modern airplane is **Mod-EZ**, spot id `mod-ez`.
- Test commands: `.venv/bin/python -m pytest -q` and `(cd guide/lab && npm test && npm run typecheck)`.

## Review Focus

1. A `decide` for an option id not in the record → HTTP 400, record file byte-identical (Task 6).
2. The council endpoint times out or returns non-JSON → the reply shows an error, the transcript logs it, the record is unchanged (Tasks 5, 6).
3. A hand edit that changes a `decided` record's decision without a `reopened` history entry → `hangar.records.validate_all` fails (Task 1).
4. `briefing.html` opened on the public site with no `/api/` → read-only view, no chat or decide controls rendered (Task 7).
5. A crash mid-write → the record file is either old or new, never partial (atomic temp+rename; Task 6).

### Task 2: Mission calculator

**Files:**
- Create: `hangar/mission.py`, `data/hangar/mod-ez/mission.yaml`, `data/hangar/mod-ez/powerplants.yaml`
- Test: `tests/hangar/test_mission.py`

**Interfaces:**
- Consumes: `core.ledger.load_ledger() -> dict` (keys `empty`, `loads`, `envelope`), `core.ledger.in_envelope(weight, cg_in, env) -> bool`; the book engine row (243 lb, arm 141.05; `data/mass_ledger.yaml` `engine` anchor).
- Produces:
  - `@dataclass(frozen=True) Value: v: float | None; flag: str  # sourced|derived|unknown; note: str`
  - `@dataclass(frozen=True) MissionScore: option: str; empty_lb: Value; empty_cg: Value; fuel_needed_lb: Value; takeoff_lb: Value; takeoff_cg: Value; landing_cg: Value; in_envelope: bool | None; range_full_fuel_nm: Value; block_time_h: Value; assumptions: list[str]; worst_flag: str`
  - `score(option_id: str, mission: dict | None = None, plants: dict | None = None) -> MissionScore`
  - `load_mission(private_dir: Path | None = None) -> dict` (public file, then `$HANGAR_PRIVATE_DIR/mission.yaml` overrides keys if present)

Mission file (public values, from the spec section 5a and the book): `leg_nm: 300`, `reserve_min: 30`, `occupants_lb: [155, 155]` (front, rear; abstract split of the spec's ~310 lb), `bags_lb: 15`, `cruise_ktas` and `fuel_capacity_gal` cited from `om-1980` (161 kt at 75%, 52 gal; the implementer finds the printed pages in the transcription and cites them; if not found, flag `unknown`), `fuel_density_lb_per_gal` cited (Swift's 5.87 lb/gal for UL94 after Task 3 registers it; else `unknown`).

Powerplant file: one entry per option id used in Task 3 (`o235-book`, `ul350i`, `ul350is`, `rotax-912is`, `rotax-915is`, `rotax-916is`, `deltahawk-dhk180`): `installed_lb` (Value-shaped, with cite), `cg_arm_in` (default: book engine arm 141.05, flagged `derived` with note "assumed same installed CG as the book engine"), `cruise_ff_gph` (sourced, or `derived` from cited BSFC × power with the method in `note`, or `unknown`).

Algorithm (the only part the signature doesn't determine): empty = book empty (730 lb @ 111.7) − book engine row + option installed weight at option arm; block time = leg / cruise + reserve; fuel needed = ff × block time × density; takeoff = empty + occupants at pilot/passenger arms + bags at baggage arm + fuel at fuel arm; landing = takeoff − leg fuel; `in_envelope` = both takeoff and landing CG/weight inside `envelope` (None if any input `unknown`); range = (capacity × density − reserve fuel) / (ff × density) × cruise. Every output Value's flag = worst of its inputs (`unknown` > `derived` > `sourced`).

### Task 5: Council engine

**Files:**
- Create: `hangar/council.py`
- Test: `tests/hangar/test_council.py`

**Interfaces:**
- Consumes: Task 1 `Record`, `ROLES`; `core.sources.check_citation`; Task 2 `score`.
- Produces:
  - `backbone(rec: Record) -> dict`: the pack the model may cite: record facts with cites, `book_choice`, mission scores, registry titles for every cited id.
  - `ask(rec: Record, message: str, history: list[dict], post: Callable[[dict], dict] | None = None, timeout_s: float = 120) -> CouncilReply`. Default `post` sends an OpenAI-compatible `/chat/completions` request to `$HANGAR_COUNCIL_URL` with model `$HANGAR_COUNCIL_MODEL` (no defaults in code; missing env → `CouncilUnavailable`).
  - `@dataclass CouncilReply: positions: list[dict]; reply_text: str; unknowns: list[str]; error: str | None`
  - `class CouncilUnavailable(RuntimeError)`

The system prompt (exact behavior from spec section 3a; wording is the implementer's): speak as the five roles; cite only ids present in the backbone; mark opinion as judgment; say unknown rather than estimate; keep dissent; name couplings; answer against the mission scores; never claim a part is trusted. Response format: JSON `{positions: [{role, option, confidence, reasoning, citations, judgment}], reply_text, unknowns}`.

Post-validation (deterministic, after the model returns): drop roles not in `ROLES`; any citation failing `check_citation` or absent from the backbone is removed and its position is set `judgment: true` with `reasoning` suffixed ` (uncited)`; `option` not in the record → position dropped; `confidence` outside the enum → `low`.
